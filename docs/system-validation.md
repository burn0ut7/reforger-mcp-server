# System validation

Maintainer note: `.temp/tests/` contains optional, disposable local harnesses, excluded from public downloads. Commands below require those retained harnesses; historical evidence is not shipped or regenerated by a build.

The server uses the official C# MCP SDK over stdio and Ghidra 12.1.4. Tests below exercise the real protocol and backend, not a mocked decompiler.

## Reproduce

Build: `dotnet build .temp/tests/ReforgerMcp.IntegrationTests -c Debug`.

Run the test executable with four arguments: absolute path to `dotnet.exe`, absolute server DLL path, absolute configuration path, and `basic`, `real` or `missing-runtime`. To test a self-contained package, supply its executable as the first argument and `-` as the second.

The additional `timeout` mode uses a fresh test store, a large native executable configured as `server`, and an intentionally insufficient 30-second analysis deadline. It verifies that incomplete analysis fails explicitly even when Ghidra exits zero, and cannot be queried as ready.

`basic` requires a fresh test-only data directory and a **copied** native PE executable configured as `server`. The fixture file must be directly inside that test data directory. The test appends one byte to this copy to verify content-based invalidation; never point this mode at an installed executable. It tests initialization/tool discovery, invalid input, unprepared-state errors, running preparation cancellation, explicit preparation, reuse, search, instructions, client query cancellation, stale page identity and stale binary rejection. Cancellation does not automatically replay the operation.

`real` requires prepared game targets. For each configured target it searches replication strings, checks pagination and inbound references, follows a function into every supported section and searches native symbols. It does not mutate installed files or analysis projects. Inspect raw results separately when assessing semantics; protocol success alone is not proof of correct decompilation.

`missing-runtime` requires a configuration whose `javaHome` points to an absent test path. It confirms that preparation returns an explicit tool error rather than starting another backend.

`corrupt-manifest` requires a test-owned executable copy inside its data directory. It writes invalid target metadata, checks that the target is unavailable, then explicitly rebuilds and cancels. The damaged manifest must remain retired.

`.temp/tests/CrashAndRestart.ps1` (PowerShell 7) takes `-Dotnet`, `-ServerDll`, `-Configuration` and a fresh absolute `-TestDirectory`. It starts preparation on a test-owned executable copy, kills only the test MCP host, verifies its Java child exits, then restarts the host and checks the job is interrupted with no published incomplete analysis.

## Acceptance boundaries

- Actual MCP requests must retrieve bounded, address-linked code and context from the configured native binaries.
- Installed binary hashes must remain unchanged.
- A changed binary or analysis identity must not reuse a stale project or page.
- Cancellation and missing runtimes must produce explicit outcomes, with no alternate path.
- Global analysis errors, per-function warnings, inferred signatures and unresolved computed calls must remain visible.
- A packaged server must start and answer MCP requests independently of the source checkout.
- Mod API validity, live Workbench operations and full semantic equivalence are outside this capability.

Local raw evidence is under `.temp/local/evidence/` and `.temp/artifacts/native-index/`, both ignored by Git because they contain machine paths and proprietary binary-derived data. Final run results and limitations are recorded after validation below.
