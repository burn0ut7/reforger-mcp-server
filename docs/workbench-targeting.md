# Workbench authoring operations

Maintainer note: `.temp/tests/` contains optional, disposable local harnesses, excluded from public downloads. Commands below require those retained harnesses; historical evidence is not shipped or regenerated by a build.

These tools use the existing main-thread native dispatcher and the exact Workbench 1.8.0.13 / Qt 6.8.3 profile. Unsupported binaries fail explicitly. Editor operations call their owning functions directly; no Enforce adapter, UI traversal, mod annotations or fixture-specific behavior is required. Runtime inspection and invocation have a separate owner documented in [Workbench runtime](workbench-runtime.md).

## Discovery and inspection

`workbench_query_entities` searches loaded editor sources by name substring, exact class, exact immediate prefab path, subscene and layer. Results include IDs, lock state and active-subscene membership. Use the observed `processId` and exact `expectedWorld` (`$Addon:worlds/name.ent`). Entity IDs belong to that loaded world; requery after reopening it.

Continue `nextOffset` with identical filters. An empty page can have a continuation. Pages are observations, not a frozen set. Population-count changes return `population_changed`; equal-count replacements are not reliably detected. Each callback reads at most 128 slots, each request scans at most 8192 slots and checks a roughly one-second yielding budget between callbacks. A running native call cannot be preempted. `truncatedCandidates` and `textFilterCoverage` report incomplete text filtering; truncated candidates are excluded from text matches. An empty filtered result is not necessarily proof of absence.

`prefabPath` is an immediate ancestor path, not a GUID-qualified identity or a transitive ancestor search. Class filtering is exact, not a derived-class query. No spatial predicate or bulk mutation is advertised.

`workbench_inspect_entity` accepts `section: components`, `properties` or `objects`. Use an inspected component index, or `component: -1` for entity properties. Nested `path` entries are `{ "property": "m_Config" }` for an object or `{ "property": "m_Items", "index": 0 }` for an object-array member. Paths have at most eight entries. `section: objects` also requires the array's `property` name and supports pagination.

Property results distinguish:

- `serializedValue`: native authoring serialization.
- `resolvedValue`: effective assignment or schema default, for supported value types.
- `valueOrigin`: instance, definition, ancestor or schema_default.
- `localOverride`: assignment owned by the selected edit scope, including nested-container ownership.
- `supplyingAncestor`: assigning resource path when recoverable; `provenanceState: unavailable` preserves missing provenance. This path is not a GUID-qualified identity.

Empty serialized text alone does not establish an empty effective value. Object containers are traversed through paths, not serialized as scalar values. Runtime fields are separate from these authoring observations. Text truncation is explicit and prevents editing.

## Editing and arrays

`workbench_edit_entity` consumes a connection-local `editToken` valid for 120 seconds. Supported actions:

| Action | Inputs and effect |
| --- | --- |
| set / clear | `key` is the inspected property; set takes typed JSON `value`. Clear restores inheritance/defaults. |
| add_component / remove_component | Class-name `key` or inspected `component` index, using a components token. |
| insert_object / remove_object | An objects token and `index`; insertion also takes the object class as `key`. |
| insert_value / remove_value | A properties token, array-property `key`, and `index`; insertion takes one typed `value`. |

Scalar support includes finite float, vectors, 32-bit integer, boolean, string and resource-name properties. Value arrays support native float, vector, integer and string arrays. Set takes a JSON array; Workbench exposes script boolean arrays as native integer arrays, using 0/1. `arrayCount` comes from native storage. Insert/remove reuse the same whole-property setter and undo machinery, checking observed serialization, native array count and override state before editing. Empty arrays are supported. The native comma-delimited format cannot represent empty string entries or commas inside entries; these inputs are rejected. Existing ambiguous serialization is rejected for entry edits; an explicit whole-array replacement remains possible.

Object-array insertion and local-entry removal use the native object-array commands. **Removing an inherited member is explicitly unsupported:** live testing showed that the native remove command did not persist the deletion after save/reopen. The server rejects it before mutation. Edit the defining prefab to remove that definition's local entry. Local entries added to inherited arrays can be removed. Creating a missing single-object property is not provided; inspect/edit existing objects or insert object-array members.

Tokens retain process, document, source, component, path, class and observed property identity. An accepted dispatch consumes all outstanding observations. Native mutations recheck identities and property text/override state before applying one editor action. MCP opens, reloads, history actions and Play transitions invalidate observations. Pointer identities are session observations, not durable handles; external lifecycle changes require reinspection. Timeout/cancellation after dispatch is uncertain: inspect state rather than replaying.

World-instance edits require an unlocked layer hierarchy and the active subscene. An unlocked inherited subscene is still read-only. The setter uses the entity root plus its container path so the editor creates local overrides instead of modifying shared prefab sources. `updated` means the native operation and action closure succeeded; inspect for readback and save separately.

## Prefab definitions and inherited resources

`workbench_open_prefab(processId, resourceName)` opens an existing GUID-qualified `.et` resource, verifies native prefab mode and returns `rootEntityId`. It replaces the clean document and refuses unsaved changes or Play.

`workbench_inspect_prefab(processId, prefabResource, rootEntityId, ...)` provides the same component/property/object sections and paths. Its tokens carry `editScope: prefab_definition`; `workbench_edit_entity` then edits that definition through the same native setter. World-instance tokens cannot silently become definition edits. Editing a shared definition intentionally affects its inheritors.

`workbench_save_prefab_definition` saves the current prefab document through the owning prefab-save operation and reports whether its modified state cleared. It includes pending definition edits in that document, not just edits made by MCP. It is distinct from `workbench_save_prefab`, which exports an entity to a new prefab.

`workbench_create_child_prefab(processId, ancestorResource, prefabPath)` creates a detached inherited resource through Workbench's resource-creation owner. Supply a GUID-qualified ancestor and an absolute new `.et` path in an existing writable addon directory. Existing resource or metadata files are rejected. It does not create/delete a temporary world entity. `created` requires native success, resource-database acknowledgement, new metadata identity and a serialized ancestor matching the requested GUID. An incomplete result can leave files; reconcile them before any further attempt. Resource creation is outside world undo.

## World save and history

`workbench_save_world(processId, expectedWorld)` saves current world/layer changes through the owning native operation, including user edits. It reports the native result and remaining modified state. This is not Save As or prefab export.

`workbench_history_status` reports undo/redo availability and history position. `workbench_history(action: undo|redo)` invokes one history action and reports the observed position change. History includes user actions, not just MCP edits. These tools require the exact world and refuse Play, prefab mode, dialogs and active edit actions. They invalidate edit tokens and never retry automatically.
